# 00-AI督导与网站内容更新指南

> **⚠️ AI 督导必读 (CRITICAL FOR AI AGENTS)**：
> Please read this document before making any content or structural updates to the personal website.

## 1. 核心架构说明：反向软链接机制

为了兼顾「在 Obsidian 外部根目录直接编辑笔记」与「Vercel 云端独立项目正确打包」，本项目采用了**反向软链接机制**：

- **真实的知识库存储位置**：`个人网站/src/content/` (所有文件都以实体文件保存在该 GitHub 仓库目录下，以确保 Vercel 打包时不会遇到丢失外部文件的问题)
- **快捷访问入口**：外层的 `个人网站内容` 是一个指向 `个人网站/src/content/` 的软链接 (symlink)。

**✅ 正确操作结论**：
无论是用户还是 AI，**编辑内容时既可以在 `个人网站/src/content/` 里操作，也可以在外层的 `个人网站内容/` 里操作。** 在外部快捷方式里的任何修改，都会自动、实时地反映在真实的 Git 仓库内。

---

## 2. 网站更新标准工作流 (SOP)

当用户要求“更新网站内容”、“发布一篇新博客”、“同步一下最新的简历”时，AI 理应按照以下标准步骤操作：

### 步骤一：在目录中创建或更新内容
你可以直接在 `个人网站内容/` (或 `个人网站/src/content/`) 对应的目录下进行 Markdown 写作、覆盖。例如简历应该覆盖 `resume/main.md`，博客应该放在 `blog/` 目录下。

### 步骤二：提交与发布 (Git Push)
内容修改完毕后，**必须**进入真实的 Git 仓库目录下完成提交与推送。推送到 `main` 分支后，Vercel 将自动抓取并重构网站。

```bash
cd 个人网站
git add src/content/
git commit -m "content: update XXXX"
git push
```
*(注意：请用规范的 commit message 描述本次更新。)*

### 步骤三：启动本地预览验证 (如需)
如果用户要求在发布前本地预览效果，需先执行：
```bash
cd 个人网站
npm run dev
```
然后告知用户通过 `http://localhost:4321` 进行本地检查。

## 3. 防错处理 (Troubleshooting)

- **千万不要**：擅自删除 `个人网站内容` 软链接并替换成普通实体文件夹（这会导致本指南第 1 点所述的“内外版本脱节”问题重演）。
- **如果本地无法预览**：先通过终端确保 `lsof -i:4321` 端口情况，如果未启动，记得在后台执行 `npm run dev` 运行起来。如果要暴露给局域网其他设备，需要增加 `--host` 参数。
- **关于图片与附件**：请确保文中使用的图片路径正确。Astro 对于放入 `src/content/` 内和 `public/` 的图片有着不同的依赖路径解析方式。通常优先放在文章的相对目录内引用，或直接放在外部图床。
